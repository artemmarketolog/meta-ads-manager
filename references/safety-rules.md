# Правила безопасности: лимиты Meta и что считается write

## Что реально ограничивает Meta

Документация Marketing API → Rate Limiting. Цифры для Full access; для Limited — `app-setup.md`.

| Лимит | Значение (Full access) | Ошибка |
|---|---|---|
| Очки кабинета (чтение 1, изменение 3) | 9000 за 5 минут, при превышении блок на 60 с | 17/2446079, 613/1487742 |
| Мутации (create/edit кампаний, групп, объявлений) | 100 запросов/с на пару приложение + кабинет | 613/5044001 |
| BUC ads_management | 100000 + 40 × активных объявлений в час | 80004 (и другие 800xx) |
| Бюджет группы | 4 смены в час, дальше бюджет группы заблокирован на час | 613/1487632 |
| spend_cap кабинета | 10 смен в день | 17/1885172 |
| Создание объявлений | зависит от дневного лимита трат кабинета | 613/1487225 |
| Insights | на уровне приложения | 4/1504022, 4/1504039 |
| Общий лимит приложения | 200 × активных пользователей в час | 4 |

Рекомендация Meta одна: не слать всплесками, при ошибке лимита — отступить. Фиксированных пауз между запросами
документация не требует. Блокировка за лимит — временная (минута, час для бюджета), это не бан кабинета. Баны бывают
за содержание рекламы, оплату и подозрительные входы, а не за темп API в пределах лимитов. Изменения по одному —
это 1–2 в секунду, в десятки раз ниже лимитов Full access.

## Жёсткие правила

### 1. Write только через meta_api.py / meta_launch.py
- `curl -X POST`, `requests.post`, `facebook_business` к write-эндпоинтам запрещены.
- Тонкие скрипты могут делать `from meta_api import MetaAdsAPI` и звать публичные методы
  (`create_*`, `pause`, `activate`, `update_entity`, uploads, `validate_*`); `_request(..., is_write=True)` напрямую нельзя.
- `validate_only` и `generatepreviews` ничего не создают и считаются чтением.

### 2. Темп
- Без фиксированных пауз; на реальной ошибке лимита (коды выше) — стоп без повторов, проверить кабинет только чтением,
  продолжить через 5 минут; для 1487632 — через час и только по этой группе; для code 4 — не раньше чем через 15 минут.
- Предупреждение заголовка usage выше 70% — не стоп.
- Параллельные запуски на разных кабинетах допустимы; на одном кабинете — один процесс за раз.
- batch-команды до 25 ID — защита от ошибки человека, не лимит Meta.
- Массовые выгрузки статистики и медиа — последовательно, без потоков, лучше ночью: `GET /<video_id>` по одному ест
  общий лимит приложения и может заблокировать всё приложение на час.

### 3. Бюджет
- Максимум 3 смены бюджета на сущность в час (Meta: 4); скрипт блокирует сам, слот тратится только после успеха.
- Бюджеты в центах валюты кабинета: `1200` = 12.00.

### 4. Staging-gate и запуск
- Новая кампания: campaign `PAUSED`, дети `ACTIVE`. Группа в активной кампании: adset `PAUSED`, ads `ACTIVE`.
  Объявление в активной группе: ad `PAUSED`. Скрипт блокирует `ACTIVE` ребёнка без выключенного родителя.
- `activate adset` сам включает выключенную кампанию-родителя: в выключенной кампании группу так не «восстанавливать».
- `--activate` не ставить, если просили только подготовить. Когда запускать — `SKILL.md`, «Когда запускать».

### 5. Readback и превью
- После write скрипт читает затронутые поля. Для дерева: итог лаунчера + `status`.
- `--check-previews` ловит ошибки рендера и рисует лист картинок; обрезку и обложки смотреть глазами по листу.
  `ACTIVE` без работающего превью = 0 показов.

### 5a. Никаких автоматических изменений креатива
- `create_creative` сам ставит OPT_OUT и блокирует OPT_IN в любом пути создания; лаунчер перед включением читает
  автоулучшения финальных креативов. `is_dynamic_creative=true` заблокирован. Мультиобъявления выключены.

### 5b. Запрещённые плейсменты
- Audience Network и Marketplace никогда. `create_adset`/`validate_adset` блокируют их и автоплейсменты;
  копии `/copies` проверяются по readback и не включаются с нарушениями.
- Instagram Explore снят Meta в v26 — вычищается автоматически.

### 6. Логирование
- Каждый write и validate пишется в `~/.local/share/meta-ads-manager/logs/meta_api_writes.log`: метод, эндпоинт, ID,
  статус ответа. Токены, тексты объявлений и таргетинг в лог не пишутся.

### 7. Что не делать никогда
- Не гадать биндинги (Instagram, номер WhatsApp, форму): `clients.json`, `whatsapp-numbers`, рабочий креатив,
  `validate-ctwa` / `--validate-only`.
- Не пересоздавать дерево при частичной ошибке: перезапустить ту же спеку.
- Не слать обратно сырой readback креатива (`standard_enhancements`, id у adlabels, `image_url`+`image_hash`).
- Не прогонять `.format()` по строкам с макросами `{{campaign.name}}`: подставлять через `replace`.
- `delete` только по явной просьбе; по умолчанию `pause`.
- Плановое выключение («выключи завтра в 9») — не через `end_time` кампании или групп, а отложенной командой
  `meta_api.py pause campaign <id>` (at, cron, launchd/systemd-таймер) на нужное время; сообщить, когда сработает.

## Что безопасно без meta_api.py
- GET (статусы, статистика, структура) с минимальными `fields`; read-only batch для независимых GET.
- `meta_api.py insights`, `doctor.py`.

## Если кабинет всё-таки заблокировали
1. Не создавать новый кабинет.
2. `meta_api.py log 200` — лог как доказательство.
3. Апелляция через Business Help Center, ждать 1–7 дней.
