# Разрешения токена: что отмечать и зачем

Агент объясняет ученику этот список, когда готовит промпт 04 (`prompts/desktop/04-system-user-token.md`), и подставляет
строку `{{PERMISSIONS}}`. `doctor.py` проверяет ровно эти разрешения.

## Обязательные — без них скилл не работает

| Разрешение | Зачем | Без него |
|---|---|---|
| `ads_management` | создавать и менять кампании, группы, объявления, бюджеты, паузу | ни одного write |
| `ads_read` | статус, статистика, превью объявлений | нет `status`, `insights`, листа превью |
| `business_management` | видеть активы бизнес-портфолио, номера WhatsApp, партнёрские кабинеты | кабинеты клиентов и WhatsApp не видны |
| `pages_show_list` | список страниц, доступных токену | нельзя выбрать страницу для креатива |
| `pages_read_engagement` | читать страницу и связанный с ней Instagram | не найти `instagram_user_id` страницы |
| `pages_manage_ads` | публиковать рекламу от имени страницы, лид-формы | креатив не создаётся (страница «чужая») |

## Рекомендуемые — для части сценариев

| Разрешение | Зачем | Сценарии |
|---|---|---|
| `instagram_basic` | Instagram-аккаунты и их публикации | `ig_profile_post` (продвижение готового поста), `ig-media` |
| `leads_retrieval` | выгружать заявки из лид-форм | лид-формы, если заявки забираются по API |
| `whatsapp_business_management` | номера WhatsApp Business по портфолио | `whatsapp-numbers`, подсказки номеров в `doctor.py discover` |

Строка для промпта 04:

```text
ads_management, ads_read, business_management, pages_show_list, pages_read_engagement, pages_manage_ads,
instagram_basic, leads_retrieval, whatsapp_business_management
```

## Чего не отмечать

- `instagram_manage_messages`, `pages_messaging`, `whatsapp_business_messaging` — переписка от имени бизнеса,
  к рекламе не относится, а у Meta это отдельная проверка.
- `catalog_management` — только для рекламы каталога (в этом скилле нет).
- Всё, что начинается с `threads_`, `instagram_content_publish`, `publish_video` — публикация контента, не реклама.

Меньше разрешений — меньше вреда, если токен утечёт.

## Доступ к активам ≠ разрешения

Разрешение говорит, *что* токен умеет; назначенные активы — *где*. Системному пользователю в бизнес-портфолио
назначают:

| Актив | Уровень | Зачем |
|---|---|---|
| Рекламный кабинет | «Управление кампаниями» + «Просмотр эффективности» | запуск и статистика |
| Страница | полный доступ (минимум Реклама, Статистика, Контент) | креативы от имени страницы, лид-формы |
| Instagram | полный доступ | объявления от имени Instagram, продвижение постов |
| Пиксель / набор данных | Управление | оптимизация на заявки с сайта |
| WhatsApp | полный доступ или просмотр | номера для рекламы в WhatsApp |

Новый актив (клиент) назначается тому же системному пользователю — токен перевыпускать не нужно.

## Уровни доступа приложения

- **Стандартный доступ** к `ads_management`/`ads_read` (выдаётся сразу) достаточен, когда приложение работает с
  кабинетами своего бизнес-портфолио — своими и партнёрскими (клиент дал доступ портфолио). Это наш случай:
  токен принадлежит системному пользователю того же портфолио, что и приложение.
- **Расширенный доступ** (App Review) нужен, только если в ваше приложение будут входить чужие люди своими
  аккаунтами Facebook. Для работы с клиентами через партнёрский доступ — не нужен.
- **Marketing API Access Tier**: новое приложение — Limited (≈20 изменений за 5 минут на кабинет), после 500 вызовов
  за 15 дней с ошибками меньше 15% — кнопка Upgrade до Full (промпт 08).
