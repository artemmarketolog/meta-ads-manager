# Подключение ученика к Meta Ads: сценарий для агента

Ты — Claude Code (или Codex) ученика. Твоя задача — за 20–40 минут довести его от «ничего нет» до работающего
`doctor.py` и первого проверочного запуска. Кликать в интерфейсе Meta будет **Claude Desktop** ученика (у него есть
браузер); ты готовишь ему промпты, объясняешь, что и зачем, принимаешь токен и проверяешь результат.

Говори просто, по-русски, коротко. Ученик может не знать слов «портфолио», «системный пользователь», «токен» —
объясняй одной фразой, когда слово появляется впервые (`app-setup.md`).

## 0. Старт

```bash
cd <папка скилла>          # ~/.claude/skills/meta-ads-manager или ~/.agents/skills/meta-ads-manager
python3 setup.py           # .venv, ~/.config/meta-ads-manager/meta.env и clients.json
python3 setup.py --check
```

Если `META_TOKEN задан` — сразу шаг 5 (`doctor.py`). Иначе — по порядку.

## 1. Короткое интервью (одним сообщением, 4 вопроса)

1. Есть ли у вас бизнес-портфолио Meta (business.facebook.com) и рекламный кабинет? Свой или только клиентов?
2. Какие клиенты будут на старте: название, есть ли у них свой кабинет и страница?
3. Есть ли сайт со страницей «Политика конфиденциальности»? (нужен для режима Live приложения)
4. Где вы запускаете меня: на своём Mac/ПК или на сервере? Установлен ли Claude Desktop с доступом к браузеру
   (Claude in Chrome)?

Не знает — не страшно: начни с промпта 01, он сам всё выпишет.

## 2. Промпт 01 — снять показания

Дай ученику `prompts/desktop/01-audit.md`, вставив в `{{RULES}}` текст `prompts/_rules.md` целиком.
Объясни: «Это только чтение, Claude Desktop ничего не меняет. Вставьте промпт в Claude Desktop и пришлите мне его отчёт».

По отчёту реши, какие шаги нужны:

| В отчёте | Дальше |
|---|---|
| нет портфолио или в нём нет кабинета/страницы | промпт 02 |
| нет приложения с Marketing API | промпт 03 |
| приложение есть, режим Development | промпт 03 с п. 4 (только перевод в Live) |
| нет системного пользователя или токена | промпт 04 |
| есть кабинеты клиентов вне портфолио | промпт 05 (после токена) |

## 3. Как выдавать промпты Claude Desktop

- Каждый промпт — **один блок кода**, готовый к копированию: `prompts/_rules.md` + текст шага, все `{{…}}`
  заменены на значения ученика. Пустых плейсхолдеров не оставлять; неизвестное — спросить у ученика.
- Перед блоком — одна-две фразы, что сделает Desktop и почему это безопасно.
- После — что прислать обратно («пришлите отчёт Claude Desktop целиком»).
- Один шаг за раз. Следующий промпт — только после отчёта по предыдущему.
- `{{PERMISSIONS}}` — строка из `permissions.md`. Перед промптом 04 коротко объясни, что даёт каждое
  разрешение (таблица там же) — ученик должен понимать, к чему даёт доступ.
- `{{APP_NAME}}` — «<название агентства> Ads»; `{{SYSTEM_USER_NAME}}` — «Claude Ads» (если ученик не против).

## 4. Приём токена — только так

Токен никогда не проходит через чат: ни через тебя, ни через Claude Desktop.

- **Claude Code на том же компьютере, где браузер** (обычный случай): Desktop нажимает «Копировать», ученик пишет
  тебе «токен в буфере». Ты запускаешь:
  ```bash
  python3 setup.py token --from-clipboard
  ```
  Скрипт проверяет токен в Meta (`/debug_token`), пишет в `meta.env` (chmod 600), очищает буфер и печатает только
  тип, приложение, срок и последние 4 символа.
- **Claude Code на сервере**: попроси ученика самому открыть терминал сервера и выполнить
  `python3 <путь>/setup.py token` — ввод скрытый. Ты ждёшь «готово» и идёшь дальше.
- Если ученик всё-таки вставил токен в чат — не используй его. Попроси отозвать (промпт 09) и выпустить новый (04).
  Это правило без исключений: чат сохраняется в истории.

## 5. Проверка

```bash
.venv/bin/python scripts/doctor.py
```

Разбор вывода для ученика:

| Строка | Что значит | Что делать |
|---|---|---|
| `❌ нет разрешения …` | при выпуске не отметили разрешение | промпт 04, шаги 4–5 (новый маркер со всеми разрешениями), снова `setup.py token` |
| `❌ токену не назначен ни один рекламный кабинет` | активы не назначены системному пользователю | промпт 04, шаг 2 |
| `⚠️ … Limited access` | новое приложение, лимиты маленькие | нормально; запуски частями, через 1–2 недели промпт 08 |
| `⚠️ Это личный токен пользователя` | токен из Graph API Explorer | перейти на системного пользователя (промпт 04) |
| `❌ токен не принят Meta` | отозван, приложение удалено или опечатка | промпт 04, новый маркер |

## 6. Клиенты

```bash
.venv/bin/python scripts/doctor.py discover            # что видно по всем кабинетам
.venv/bin/python scripts/doctor.py discover --write    # черновики в ~/.config/meta-ads-manager/clients.json
```

Открой `clients.json`, вместе с учеником допиши: короткие `aliases` (как он называет клиента), `geo` (город латиницей
для имён кампаний), `whatsapp_phone_number`, `lead_gen_form_id`, `notes` (запреты и пожелания клиента).
Пример полей — `examples/clients.example.json`. Новый клиент позже — промпт 05, потом `discover --account=act_… --write`.

## 7. Первый проверочный запуск (ничего не создаёт)

Возьми клиента и простой сценарий (обычно `ctwa_static` или `lead_site_static`), собери спеку по
`examples/specs/`, и:

```bash
.venv/bin/python scripts/meta_launch.py --spec spec.json --validate-only   # Meta проверяет всё, ничего не создаёт
.venv/bin/python scripts/meta_launch.py --spec spec.json --preview-only    # лист превью картинкой
```

Покажи ученику лист превью (`…-previews.jpg` рядом со state) и объясни, что видно в каждой колонке.
Для проверки группы `--validate-only` нужна любая существующая кампания кабинета с бюджетом на уровне групп
(`validate_campaign_id` в спеке). Если её нет, кампания и креативы всё равно проверятся, а группа будет пропущена —
её проверит первый настоящий запуск (кампания создаётся выключенной).

## 8. Итог для ученика

Коротко: что подключено (кабинеты, клиенты), уровень доступа, где лежат токен и клиенты, как сказать тебе
«запусти рекламу» в следующий раз (примеры фраз — README → «Как пользоваться»). Дальше работа — по `SKILL.md`.
