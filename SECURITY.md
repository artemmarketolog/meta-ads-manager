# Безопасность и личные данные

## Что и где хранится

Скилл читает только свои файлы, вне репозитория:

| Файл | Что внутри | Права |
|---|---|---|
| `~/.config/meta-ads-manager/meta.env` | токен Meta и настройки | 600 |
| `~/.config/meta-ads-manager/clients.json` | ID кабинетов, страниц, Instagram, номера WhatsApp, пиксели клиентов | 600 |
| `~/.local/share/meta-ads-manager/state/` | state запусков, листы превью | каталог 700 |
| `~/.local/share/meta-ads-manager/logs/` | лог write-запросов: метод, эндпоинт, ID, код ответа | каталог 700 |

Скрипты не ищут ключи в других проектах, истории агента, профиле браузера или системном хранилище паролей.
В лог не пишутся токены, тексты объявлений и таргетинг. Запросы уходят только в `graph.facebook.com`;
лист превью открывает ссылки превью Meta в локальном headless Chrome. Телеметрии и ботов нет.

## Токен

- Токен никогда не проходит через чат с агентом. Приём — `python3 setup.py token --from-clipboard` (буфер обмена,
  после сохранения очищается) или `python3 setup.py token` (скрытый ввод в терминале). Скрипт печатает только тип,
  приложение, срок и последние 4 символа.
- Рекомендуемый токен — системного пользователя бизнес-портфолио: видит только назначенные активы, отзывается
  в один клик (`prompts/desktop/09-revoke-token.md`).
- Минимум разрешений — `references/permissions.md`. Переписку, публикацию контента и каталоги не отмечать.

## Если токен утёк

1. Отозвать: промпт 09 (Business settings → System users → Revoke tokens).
2. Выпустить новый: промпт 04, шаги 4–5, и `python3 setup.py token`.
3. Если токен попал в git — после отзыва почистить историю; отзыв важнее чистки.

## Claude Desktop

Промпты начинаются с общих правил (`prompts/_rules.md`): пароли, коды и подтверждение личности — только человек;
токены не пересказываются и никуда не вставляются; оплата, бюджеты и включение рекламы не трогаются; ничего не удаляется
и не отправляется на проверку без прямого указания. Это инструкции модели, а не техническая защита: смотрите, что
делает Desktop, и не оставляйте его без присмотра на страницах оплаты.

## Сообщить об уязвимости

GitHub → **Security → Report a vulnerability**. Не публикуйте токены, ID клиентов и скриншоты кабинетов в открытых issues.
